# InterceptPilot 1.2.3

## Highlights

- AI-generated rule bundles now default `match.resourceType` to `ANY`, so they reliably intercept application requests instead of silently passing them through.

## In-App Update Notes

The in-app update modal for version `1.2.3` shows a patch-specific note (`releaseNotes.items.aiTemplateResourceType`) describing the AI rule-bundle resource-type fix, localized in PT, EN, and ES.

## Fixes

- Changed the AI prompt template (`makeTemplateRule`) to seed `resourceType: "ANY"` instead of `"Fetch"`. The previous default produced bundles whose rules matched only the exact CDP resource type `Fetch`, so requests from libraries like ofetch or axios (frequently reported by the DevTools protocol as `XHR`) were never intercepted and reached the real network.
- Added a guidance line to the AI prompt recommending `resourceType: "ANY"` and explaining that `Fetch`/`XHR` match only the exact CDP resource type. Applied to the English fallback and the `pt-BR`, `en` and `es` locales.

## Scope Notes

This patch release does not change extension permissions, Manifest V3 permission lists, capture runtime behavior, the rule engine, hit state logic, rules file organization, MCP/local bridge behavior, Native Messaging, or a local companion app. Existing rules and bundles are unaffected; only newly AI-generated bundles change their seeded default.

## Manual Validation Recommended

- Open `Templates` > `Copy AI prompt`, generate a bundle for an app endpoint, and confirm each rule comes back with `resourceType: "ANY"`.
- Import the generated bundle, enable one rule, and confirm it intercepts a real `fetch`/ofetch/axios request in the page (response is the mock, not the live API).
- Confirm the prompt text shows the new resource-type guidance line in PT, EN, and ES.
- Confirm the in-app update modal shows version `1.2.3` with the AI resource-type note in PT, EN, and ES.
